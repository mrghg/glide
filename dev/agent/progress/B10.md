- reference issues:
  - DATEM `stat_pgm/statmain/statmain.f` lines 311–321: the comment says the -b resampling is seeded from the clock, but the clock value is stored in RPCT, which the first `RANDOM_NUMBER(RPCT)` overwrites, and `RANDOM_SEED` is never called. The sequence is the compiler's default (random per run with gfortran ≥ 7; possibly fixed with ifort). Effect: ±0.005 on CAPTEX ranks; published -b ranks are not exactly reproducible. B10 takes a seed instead; GLIDE does not copy the behaviour.
  - statmain.f SPATIAL (lines 1120–1157): FAR, POD and TS use the raw arrays, so missing records (-1) count as below the contingency level and the -z zero is ignored. Does not enter the rank. B10 copies it only to reproduce the printed files.
  - statmain.f SORT (line 1911): with ≤ 1 value it returns without setting the percentiles, so KSP and the rank use undefined values for tiny subsets (e.g. `-p` with one plume pair). Not hit by the posted files; B10 returns NaN.
  - DATEM `exp_data/etex/meas-t1.txt`, station 6028 (D28), 1994-10-23 21:00, 600 pg m-3 where JRC v1.1 has 0.00 (flag 01). Physically implausible 5–8 h after the release began in Brittany; undocumented. One of 3,105 pairs; also adds 7 pairs to the ATMES-II filter count.
  - DATEM ETEX D10 interval 2 is the pre-v1.1 value (1.76; JRC changed it to -.88 on 5 May 1996), and D13 and F10 have the old locations. DATEM's copy is the ATMES-era data, which explains the published 1,423 against 1,415 on v1.1.
  - DATEM `exp_data/acurate/meas-t0.txt` names itself `meas-t1.txt` in line 1. Cosmetic.
  - Mosca et al. (1998) KS values (72–365) are not percentages and the paper does not define them; the published FA2 (28–37%) cannot be matched to either zero convention without the report. Not a confirmed error, but the comparison is uncertain until EUR 17756 EN is read.
