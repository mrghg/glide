- recommendation (bf16 by default): **no**, so no decision record. It is harmless (every parity measure is below the seed-to-seed noise; with the random numbers fixed it moves 0-40 m totals by 0.06% after 12 h), but it buys nothing measurable: it touches only the wind gather, ~0.4 ms of a ~14.5 ms step in a microbenchmark and not resolvable in the full runs, while the wall is set by met_fetch (50-55%), which it cannot reduce. Worth revisiting only if the step becomes the bottleneck (after a met_fetch fix) or if the met cache moves to the device, where halving the wind stacks' memory would matter.
- met_fetch proposal (item 3; not implemented): see the PR. Measured: 5.1 s wall per window, ~84% reading/decompressing the 137-level source store, ~8% resampling; concurrent threads did not raise throughput (node loaded).
